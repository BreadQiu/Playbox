# Playbox v0.1.0 and Blocky 24 Public Release Plan

## Goal

Publish a public Playbox repository containing a game catalog and the first
game, Blocky 24, with a verified GitHub Pages deployment and a v0.1.0 GitHub
Release.

## Repository Shape

- Root package: `playbox@0.1.0`, npm workspace owner for `games/*`.
- Catalog: static Playbox landing page at the Pages repository root.
- First game: `@playbox/blocky-24@0.1.0` under `games/blocky-24/`.
- Public URLs: `/Playbox/` and `/Playbox/blocky-24/`.
- MIT license with `Copyright (c) 2026 Playbox contributors`.
- Repository description: `A growing collection of playful browser games. First release: Blocky 24.`

## Implementation Tasks

1. Preserve the completed Blocky 24 work in Git, then create a Playbox release
   branch and move the game into the workspace without changing its behavior.
2. Add the Playbox landing page with one Blocky 24 game card, preview image,
   version badge, responsive layout, keyboard focus, and reduced-motion support.
3. Rebrand the game as Blocky 24 while preserving its Chinese instructions,
   tactile/comedy sound-preview URLs, mute control, and all existing gameplay.
4. Add a unified static build that copies the catalog to `dist/` and builds
   Blocky 24 into `dist/blocky-24/` with relative assets.
5. Update the Pages workflow, README, LICENSE, package metadata, and local
   preview commands for the workspace layout.
6. Replace the Pages verifier with checks for the catalog, game deep link,
   representative merge, responsive layout, sound control, and console errors.

## Release Operations

1. Run the public-project audit and inspect all warnings.
2. Run unit tests, browser tests, production build, and Pages subpath checks.
3. Commit the packaged release, merge it into `main`, and push to the public
   `BreadQiu/Playbox` repository. If the repository already exists, inspect it
   before modifying it and never force-push.
4. Configure GitHub Actions as the Pages source, set homepage, description,
   and topics. Wait for the Pages build to reach `built`.
5. Verify the live catalog and Blocky 24 with the public HTTPS URLs.
6. Create tag `v0.1.0` and an official Release titled
   `Playbox v0.1.0 — Blocky 24`, attaching `playbox-v0.1.0.zip`.

## Acceptance

- Playbox catalog and Blocky 24 load without missing assets or browser errors.
- Blocky 24 can complete a representative drag merge under the Pages subpath.
- Desktop, 390x844 phone, and iPad layouts have no horizontal overflow.
- Audio style selection and mute control work.
- GitHub metadata, Pages status, release tag, release notes, and ZIP asset are
  all verified independently.
