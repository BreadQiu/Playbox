# 24 点拖拽合并游戏设计

## 目标

做一个部署在 GitHub Pages 的静态网页游戏，玩家打开链接后直接看到可玩的 24 点题目，无需登录、教程页或开始按钮。电脑鼠标、手机和平板触控都使用同一套拖拽合并操作。

这是单人版本。现阶段不实现账号、房间、排行榜、实时同步或对战服务器，但玩法计算保持确定性，方便以后加入对战。

## 成功标准

- 首次打开页面即可开始一局，题目和计时在首屏出现。
- 玩家能用鼠标、触控和触控笔完成合并操作；首版不提供纯键盘合并。
- 四个数字必须且只能各使用一次，最终结果为 24 时获胜。
- 随机数字可选择 `1-9` 或 `1-13`。
- 可以配置无解题是否可能出现。
- 有每题正计时、轻量的胜利和失败反馈；首版不提供音效。
- 手机、平板、桌面布局都不遮挡数字或拖拽落点。
- GitHub Pages 上无控制台错误，资源能从仓库子路径正确加载。

## 非目标

- 本阶段不做多人对战、联机房间、用户账号、云端存档或排行榜。
- 不做教学关卡、每日挑战、成就系统或复杂计分。
- 不依赖后端、数据库或运行时 API。
- 灯泡只提供原始题目的第一步提示；底部按钮可检查当前题是否有解。

## 会视为失败的情况

- 打开页面后需要先经过菜单或说明才能玩。
- 拖拽区域在手机上太小、互相重叠，或被手指完全遮挡。
- 浮点误差导致数学上等于 24 的组合被判错。
- 无解题设置开启后，所有题目仍然被强制过滤成有解题。
- 胜利或失败状态应能撤销到上一手；胜利撤销后计时仍保持暂停。
- 页面只在桌面鼠标下可用，触控拖拽与滚动互相抢占。

## 约束与产品取舍

- 游戏只使用四个数字、四则运算和括号。
- 允许中间结果为负数、分数和大数；渲染时保留精确值。
- 随机数字允许重复，四个数字独立取自当前范围。
- 每题使用正计时。换题时归零；只有出现“下一题”时暂停，失败牌面和普通撤销后继续累计，页面隐藏时暂停。
- 默认数字范围为 `1-9`，默认不出现无解题。
- 设置保存到本地浏览器；数字范围和无解题设置通过“应用并换题”生效。
- 因没有后端，所有题目都在浏览器内生成和验证。

## 已选交互方案：拖拽到运算符

开局显示四张数字卡，默认排列为 2×2。按住任意卡片并拖动超过小范围后进入拖拽模式：

1. 被拖动的卡片浮起并跟随指针，原位置保留淡色占位。
2. 被拖动卡靠近某张目标卡时，目标卡左上、右上、左下、右下渐显 `+`、`−`、`×`、`÷`；未靠近的卡不显示运算符。
3. 指针进入某个运算符落点时，或浮起卡心覆盖某个落点时，同时高亮该落点、它的目标卡和放大反馈，但不显示预计结果。
4. 在有效落点松开时，被拖动卡消失，目标卡在原位置变成结果。
5. 在无效区域松开时，卡片回到原位，不改变题目。

运算方向固定为“被拖动数 `op` 目标数”：

```text
拖动 A 到 B 右上的“−”并松开 → A − B → 结果留在 B 的位置
拖动 A 到 B 右下的“÷”并松开 → A ÷ B → 结果留在 B 的位置
```

若目标数为 0，该卡周围的除法落点保留但禁用。其他三个运算符始终可用。

### 卡片位置与合并

四张卡片对应四个固定槽位。一次合并后：

- 源卡槽变成不可见空位，不显示虚线框。
- 目标卡槽显示计算结果和新算式。
- 其他卡片不自动重排，减少位置变化造成的误操作。
- 已经用过的源数字从牌面消失，不能再参与后续运算。

三次有效合并后只剩一个结果。结果为 24 时进入胜利状态；否则进入失败状态。两种状态都允许撤销最后一步或重开本题，且不显示结果面板。

### 拖拽行为细节

- 使用 Pointer Events，统一处理鼠标、触控和触控笔。
- 卡片区域启用拖拽手势，拖拽开始后阻止页面滚动；页面其他区域仍可正常滚动。
- 设置移动阈值，避免轻点卡片时误触拖拽。
- 运算符实际命中区为桌面 56×56 CSS 像素、手机和横屏 48×48 CSS 像素；选中项分别放大约 1.22 和 1.16 倍，展开后不与任何其他落点相交。
- 拖动时若页面尺寸改变或指针取消，取消本次操作并复位。
- 撤销恢复合并前的数字、槽位、算式和操作历史，不限撤销次数；胜利状态同样可以撤销。

## 游戏规则

### 数值模型

牌面值使用有理数表示，即分子和分母两个整数。所有牌面值和中间结果都使用有理数运算，最终值与 24 做精确比较，不使用浮点容差。

显示规则：

- 整数直接显示，例如 `24`、`-3`。
- 非整数使用 `分子/分母`，例如 `3/2`。
- 分母始终为正，结果自动约分。
- 卡面显示结果值；较小字显示累计算式。

### 合并算式

每张卡同时保存值和可读算式。合并时生成新的算式，并在需要位置添加括号，确保算式阅读顺序与实际计算一致。例如：

```text
(6 − 8) × (2 + 4)
```

撤销、重开和胜利判断都基于同一份游戏状态，不依赖界面上的文本反推。

### 计时

- 每题使用正计时，显示为 `MM:SS`，超过一小时后显示 `H:MM:SS`。
- 计时精度为 1 秒，内部保留毫秒以准确累计。
- 打开设置面板或执行撤销时计时不停止。
- 浏览器标签页隐藏时暂停，重新可见时继续。
- 出现“下一题”时冻结最终时间；错误最终牌面继续计时。胜利撤销后仍保持“下一题”和暂停计时。
- 换题计时归零，重来不归零。

### 出题与无解题

题目由四个独立随机数字组成，允许重复。生成器接受一个随机源，便于测试和以后复现题目。

无解设置的含义：

- 关闭时：不断生成题目，直到穷举求解器确认该题有解。
- 开启时：从当前范围内的全部随机数字组合中直接取题，不保证有解；因此可能出现无解题。

求解器使用精确有理数和穷举成对合并，判断四个数字能否在每张牌使用一次的前提下得到 24，并可返回某个完整解法对应的第一步。

灯泡在按钮左侧、同一高度显示提示，任何后续点击、拖拽、滚动或按键都会关闭它。允许无解且原题有解时，点击灯泡会自动显示半透明白色“此题有解”；手动点击蓝色“无解”按钮则显示红色“此题有解”并继续计时，灯泡仍可点击。确认无解后显示绿色“此题无解”，暂停计时、禁用灯泡并把换题按钮改为下一题。

## 首屏与设置

首屏直接展示游戏，不设置欢迎页。

建议布局：

```text
┌─────────────────────────────────────┐
│ 24点       12:08          [设置]   │
│                                     │
│ (撤销)                      (灯泡) │
│        [ 6 ]        [ 8 ]           │
│                                     │
│        [ 2 ]        [ 4 ]           │
│                                     │
│ [此题有解/无解] [奶油重来] [奶油换题]│
└─────────────────────────────────────┘
```

设置面板包含：

- 数字范围：`1-9`“简单”或 `1-13`“困难”。
- 是否允许无解：关闭或开启。
- “应用并换题”按钮。

拖动时，只有被靠近的目标卡显示四个角落运算符圆钮。桌面端允许更大的留白和轻微桌面倾斜感；移动端以卡片和落点优先，减少装饰性区域。设置里的关闭按钮、难度选项、无解开关和绿色应用按钮在鼠标悬浮时明显放大或上移。

## 视觉与反馈方向

采用“算术游乐桌”的视觉语言：像一张可以移动数字块的桌上玩具，而不是普通表单或教学软件。

- 页面以亮黄色积木桌为底色，数字卡使用深墨描边、硬阴影和柔和色板。
- 数字本身是页面最强的视觉元素，统一使用 A 方案的加粗 `Trebuchet MS`。
- 普通牌只在奶油黄、天空蓝、草莓粉、香芋紫四色中随机，并避开当前其他牌的颜色。
- 最后一张牌为 24 时使用薄荷绿，否则使用蜜桃橙。
- 静止卡牌在 ±3.2° 内轻微倾斜；颜色和倾斜跟着具体牌面保持稳定。
- 运算符落点用圆形，位于目标卡四角，只在拖拽靠近时渐显。
- 有解状态按钮、绿色“下一题”和绿色应用按钮的硬阴影统一使用与重来按钮相同的棕色。
- 合并使用短促的收缩、数字翻面和位置接合动画。
- 胜利不使用大面积礼花；用一次整合式数值闪光和轻微的棋盘弹动。
- 尊重 `prefers-reduced-motion`，减少动画时保留颜色与文本反馈。

具体色彩、字体和装饰将在实现阶段用 `frontend-design` 落地；这里固定的是“实体数字块、即时合并反馈、数字优先”的方向。

## 技术方向

使用 Vite、TypeScript、原生 DOM 和 CSS，不引入游戏引擎或 UI 框架。原因：

- 这是卡片状态和拖拽交互，不需要 Canvas 或物理引擎。
- 原生 DOM 更容易做到可访问的按钮、文本和响应式布局。
- 构建产物是纯静态文件，适合 GitHub Pages。
- 核心规则保持为纯 TypeScript 模块，方便单元测试和未来复用。

建议模块边界：

- `game`: 牌、槽位、操作历史、合并和胜负状态。
- `math`: 有理数、算式和精确比较。
- `puzzle`: 随机出题、求解器和设置过滤。
- `timer`: 可暂停的正计时。
- `ui`: DOM 渲染、Pointer Events 拖拽、设置与响应式反馈。
- `storage`: 从本地读取和保存用户设置。

禁用服务器、登录、网络请求和对战状态。核心逻辑不读取 DOM 或浏览器存储，方便测试。

## 响应式与可访问性

- 手机竖屏：2×2 卡片，页面无横向滚动，底部操作始终可触达。
- 手机横屏与平板：增加卡片间距，不改变基本操作。
- 桌面：2×2 居中棋盘，保留鼠标操作；设置和底部控制按钮可键盘聚焦。
- 运算符按钮提供可读的按钮名称，不只靠颜色区分。
- 拖拽状态通过浮起卡、目标卡高亮和运算符放大提示当前源卡与目标运算，不提前显示计算结果。
- 支持系统减少动态效果设置。

## 测试策略

### 单元测试

- 有理数加减乘除、约分、负数分母和相等判断。
- 所有成功/失败合并方向，包括 `A − B` 与 `A ÷ B`。
- 源卡槽清空、目标卡槽更新和其他卡片位置不变。
- 撤销恢复到合并前的完整状态。
- 三次合并后的胜负判断。
- 求解器对已知有解和无解题的结果。
- 无解关闭时只生成有解题。
- 无解开启时允许生成无解题，并可通过固定随机源复现。
- 计时持续到“下一题”出现；错误牌面继续累计，胜利和无解确认后暂停，换题归零。

### 浏览器测试

- 鼠标拖拽完成一次合并。
- 手机尺寸下触控拖拽完成一次合并。
- 无效区域松开后状态不变。
- 拖动时不触发页面滚动。
- 设置变化和本地保存。
- 胜利、失败、撤销、重来和换题流程。
- 桌面、390×844 手机和 iPad 竖屏尺寸无遮挡或横向溢出。
- 页面刷新后默认直接进入可玩状态。

为自动试玩提供当前题面、槽位、计时、拖拽状态和结果状态的只读调试文本。测试以真实数值和状态为准，不通过截图猜测逻辑结果。

## GitHub Pages 上线

- Vite 使用相对资源路径，兼容 `https://用户名.github.io/仓库名/`。
- 构建产物不依赖服务端路由。
- 使用 GitHub Actions 构建并发布静态产物。
- README 提供在线地址、玩法、设置和本地运行命令。
- 上线后检查首页、主要拖拽路径、资源路径、手机布局和控制台错误。
